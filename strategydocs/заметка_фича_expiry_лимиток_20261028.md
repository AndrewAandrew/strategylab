# Заметка: фича `feat/limit-order-expiry` — TIF-списание для отдыхающих лимиток

Ветка `feat/limit-order-expiry` (база — HEAD `calibration-suite`). Это **единственная**
ветка, которая трогает ядро `strategylab/` во время калибровочного набора. Мержить или
отклонять — твоё решение; набор подтягивает её merge'ом только для прогонов spec_04.

## Зачем (контекст design §7, finding №0 спеки C)

Калибровка хотела проверить maker-механику: лимитка, которая ставится и **не**
исполняется, должна сниматься по сроку жизни (time-in-force). Ядро этого не умело:

- у `Order` не было поля TIF/expiry;
- cancel-API нет;
- reduce-only-трюк ломается о `_cancel_reduced`: он снимает **все** reduce-only заявки
  при флэте позиции — то есть «снять потом самому» тоже не вариант.

Факт «maker-механику нельзя было проверить» (design §7) — регистрируется как finding №0
спеки C. Без этой фичы `limit_pullback` либо копила бы лестницу неисполненных BUY-лимиток
(grid-эффект на ровном месте), либо дышала уровнями, которые живой брокер давно бы снял.

## Семантика (ровно одно поле, поведение по умолчанию — прежнее)

`Order(side, kind, qty, limit_price, stop_price, reduce_only, expires_in_bars=None)` —
**седьмое** поле со значением по умолчанию.

Ордер, поданный при внутреннем счётчике `seq = S`, участвует в `apply_bar` для
`S+1 … S+e`. На входе первого `apply_bar` с `seq > S + e` он **молча списывается без
Fill** (не «отменён стратегией», не событие в журнале — просто уходит из очереди, как
просроченный GTC на бирже). `expires_in_bars=None` — неограниченно: ордер отдыхает
ровно столько, сколько раньше, и весь старый набор тестов проходит **без правки ни
одного assert**.

Внутренне: очередь — `_pending: list[_Rest]`, где `_Rest(order, born)` — frozen-slots
датакласс; `born = self._seq` пишется в `submit`. Счётчик `_seq` — обычное поле
slotted-датакласса с `default=0` (не ad-hoc атрибут), инкремент в начале `apply_bar`.
Публичное свойство `pending_orders` наружу по-прежнему `list[Order]` — извлекает
`.order`. Все внутренние циклы (`_cancel_reduced`, `_apply_stops`, `_apply_exits`,
`_apply_limits`, `_apply_markets`, `_drop_resting_target`) сохраняют объекты `_Rest`,
чтобы не потерять `born`.

## Совместимость: чем доказана

1. **Тесты:** `tests/test_broker_expiry.py` — 7 новых (TTL-списание без Fill, maker-филл
   до expiry, None отдыхает вечно на 50 барах, просроченная не исполняется на позднем
   касании, expiry не трогает позицию, legacy-построение 6 позиционными аргументами,
   born переживает частичный тейк — `_drop_resting_target`/`_cancel_reduced` не двигают
   срок жизни отдыхающим заявкам). `tests/test_broker_sim.py` **не изменён** — весь
   `pytest` зелёный: **380 passed, 3 skipped** (это 373 прежних + 7 новых, прежние
   assert'ы один-в-один).
2. **Baseline-дифф (главная гарантия для прогонов):** перепрогнали харнессом весь
   spec_02 (buy_hold) и весь spec_03 (sma_cross, 4 ячейки) на ветке с фичей в
   `data/calib/after_feat/` и сравнили **целые файлы по `Get-FileHash`** с baseline:
   **16 из 16 побайтово равны** (csv обеих ног, journals, report_p). Ни число, ни
   порядок строк не шевельнулись. (Не `Compare-Object` — он пропускает перестановки.)
3. **Тип-контракт:** позиционный `BrokerSimulator(costs, intrabar)` прежний; `Order`
   frozen-slots — поле только добавлено в конец, все 14 мест-конструкторов `Order(...)`
   в пакете передают шесть позиционных аргументов (все legacy-ордеры → `None` → вечные).

## Объём диффа

- `strategylab/broker/orders.py`: +1 поле `expires_in_bars: int | None = None` + докстринг.
- `strategylab/broker/sim.py`: `_Rest`, `_seq`, списание в начале `apply_bar`,
  сохранение `_Rest` во 6 циклах, `pending_orders` → `.order`. **50 вставок, 24 удаления.**
- `tests/test_broker_expiry.py`: новый файл (7 тестов).
- Эта заметка.

## Что решает мержем

Merge'ом в `calibration-suite` фича включается только для прогонов spec_04: сама
`limit_pullback` пишется в Task 5 поверх уже слитой ветки.
Если хочешь другое время жизни (например, считать expiry по
`tif`-флагу или по таймстемпам баров) — правим здесь, до мержа; пока это минимальная
реализация ровно под замороженную в design §7 механику волн `expires_in_bars = e`.

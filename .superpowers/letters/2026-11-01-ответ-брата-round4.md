## 2. Методология (определения — ДО любых таблиц)

**Первая строка: арифметика B-колонки (maker-вход) по коду брокера.** `_limit_fill`
(sim.py:312–322): LIMIT исполняется ровно по `limit_price` при касании, комиссия
maker 0.0002·qty·price, **без проскальзывания**. Маркет-филл (sim.py:324–328):
`slipped(close)` = close·(1∓0.0005) + taker 0.0006. Стоп-филл (sim.py:185–186,
295–299): `slipped(_stop_base)` — **уровень·(1∓slip) при касании (без гэпа)**, open·(1∓slip)
при гэповом пробое; комиссия taker. TP1 (зеркало цели, sim.py:169–173): ровно по цене
уровня + maker 0.0002. Сведение окна (engine.py:219–222): `slipped(close)` + taker.
Ликвидация (sim.py:230–251): fill по «adverse»-цене бара (raw low/high) + taker, затем
`LiquidationError`. Профиль A (taker-вход, ПЕРВИЧНЫЙ): вход трактуется как маркет —
цена входа `mid·(1∓slip)`, taker-комиссия; профиль B (maker-вход, вторичный): вход
ровно по `mid`, maker 0.0002 — как исполняет брокер фактически. Обе колонки — из
одних и тех же сделок (вторая колонка пересчётом входной ноги). **Колонка B в этом
раунде не понадобилась ни разу: ни одна ячейка S не дошла до журнала (§3); арифметика
зафиксирована здесь до чисел, как требовал контракт §3.**

**Гейт маржи (`_guard_submit`, engine.py:101–142).** Перед `broker.submit` для
не-reduce-only заявки: `marked = metrics.equity + signed_qty·(close − avg_entry)` при
открытой позиции (при флэте marked = equity); `required = (|Q|·close + q·close)/leverage`.
Отклонение: marked ≤ 0 либо required > marked (равенство проходит) → `MarginError`.
Reduce-only проходит всегда. Ключевая алгебра для риск-сайзинга J/S
(`qty = equity·r/R`, r = 0.01): вход при флэте проходит гейт **только если R/цена ≥
r/lev = 0.1%**; требуемая маржа при этом = `equity·r·цена/(lev·R)`. Любая сделка с
более тесным стопом = отклонённая заявка.

**Обработка исходов MarginError / LiquidationError (зафиксировано до прогонов, §0.3).**
Харнесс гасит только `(ValueError, LiquidationError)` (harness.py:395); `MarginError`
НЕ гасится → краш процесса = результат ячейки **MARGIN_CRASH** (не баг, «счастье
замера» §3: разорение/неисполнимость). `LiquidationError` гасится → строка
«ОТКЛОНЕНО … LiquidationError …», затем SystemExit «все ячейки сетки отклонены —
артефактов прогона нет» = исход **LIQUIDATED**. Артефакты пишутся только при чистом
завершении. Один вызов = одна ячейка; краши записаны, сетка продолжена; никаких
циклов-обёрток try/except над сеткой не было. **REJECTED-колонка J/S**: число
отклонённых заявок `_guard_submit` наблюдаемо как 0 для чистых ячеек и ≥1 для
MARGIN_CRASH (первая отклонённая заявка зафиксирована в трейсбеке точными числами
required/marked; точное число последующих отклонений не наблюдаемо без изменения
харнесса, что запрещено). Во всех 12 крашах J/S вход подавался при флэте, поэтому
**marked в трейсбеке = реализованный equity счёта на момент смерти ячейки**.

**Warm-up (зафиксировано до чисел, §2 против факта).** Пререгистрация §2 требует
«не менее 200 pre-window баров». Физически это неисполнимо: ETH-бары начинаются
ровно с 1761523200 (старт f1), у BTC непосредственная предыстория f1 лежит внутри
гэпа [1735689600, 1761523200) — бары до гэпа не contiguны (агрегатор харнесса
поднимает `IncompleteBarGroup` на разрыве), а бары до 1735689600 не в зоне fit
(`ensure_fit` отверг окно). Для f2/f3 прогонные бары существуют, но симметрия фолдов
важнее (то же решение «не как в round 3», §2). Решение ведущего, зафиксировано ДО
чисел: **прогрев индикаторов происходит внутри каждого фолда, одинаково для всех 18
ячеек** (ReplayDriver стартует с `start_ts`; прегонных баров нет по построению).
«Не готов = нет сигналов» нативно классам: J — `_entry_signal` возвращает None без
значений t−1/t−2 EMA (jaguar_ema.py:161–164); S — фрактальный слой требует
подтверждения на t+2 и `_hl` из 2 баров; D — покупает с бара 0 без всякой готовности.

**Сделка и объект §8.** Журнал (`journal_p.csv`) пишет по строке на КАЖДУЮ закрытую
часть позиции (TP1 и раннер — две строки с общим `entry_ts`; trades.py:63–90), pnl
абсолютный, уже «net» (издержки внутри филлов). `n` ячейки = число строк журнала =
`metrics.trades` харнесса. Объект combined слота §8 = возврат на закрытую часть в %
нотинала: `pnl / (q·entry_price)`; отдельной гросс-колонки нет — профиль A включает
все издержки в pnl по построению (правило 5 «net без funding-поправок» выполнено
конструктивно: funding в классах отсутствует). WR = доля строк с pnl > 0.

**Bootstrap.** 1000 ресэмплов, seed 42, перцентильный, iid по сделкам (конвенция
round 3 сохранена).

**Фолды/клетка.** Клетка = класс×символ, агрегат по фолдам f1 [1761523200,1771113600),
f2 [1771113600,1780704000), f3 [1780704000,1790294400). Пустой фолд (или фолд,
погибший крашем — наблюдаемое n = 0) = провал правила 3 (то же толкование, что F2 в
round 3); пороги §8 не ослаблялись.

**S-миноры (review-strat-smc, m-1..m-5) — в наследство методологии, влияния на замер нет:**
m-2 — hard-cap исполняется на exec+241-м баре (сигнал на +240, маркет-филл следующего
бара — нативная латентность ядра); m-3 — брекет (SL/TP1) активен с бара после
исполнения, внутрибарный разворот на баре входа не защищён стопом до его закрытия;
m-4 — возрастной страж `_FVG_AGE_LIMIT = 5` под амендом свежести идентично истинен
(допустимые пары имеют возраст ровно 2) — **мёртвый код, не влияет**; m-1 — «обратный
CHoCH до TP1 не закрывает позицию» закреплено кодом, не тестом; m-5 — шероховатость
комментария-заголовка. J-стоп-филл: замороженный SL исполняется как уровень·(1∓slip)
при касании; при гэпе исполнения ниже SL брекет не ставится (R≤0) и позиция живёт
без стопа до полного выхода по close<EMA34 (info-2 ревью) — нативно унаследовано.
Вилка PESSIMISTIC первична у обоих классов (report-primary харнесса).

## 7. Красным (без сглаживания)

- **J мёртв в обеих клетках, 6/6 фолдов MARGIN_CRASH.** Три фолда (BTC-f1, ETH-f1,
  BTC-f3) умерли на ПЕРВОМ сигнале: ни одной сделки за фолд. Первый вход J-ETH-f1
  требовал маржу 474 362 при счёте 10 000 (notional 4.74 млн — в 474 раза больше
  счёта): стоп-дистанция сигнала была 0.0021% цены при линии 0.1%.
- **S мёртв в обеих клетках, 6/6 фолдов MARGIN_CRASH** — и умер «всего на 7–26% ниже
  линии»: implied R/цена 0.074–0.099% против порога 0.1%. S-ячейки успели потерять
  до −30% счёта (S-BTC-f3: equity 7 006.78 на момент смерти), но журнал этих сделок
  погиб вместе с процессом — наблюдаемое n = 0.
- **Структурный факт (не оправдание, а результат замера §3):** риск-сайзинг 1%
  с требуемой маржой notional/10 на входе при флэте математически требует
  R/цена ≥ 0.1% на КАЖДОЙ сделке; каждая более тесная сделка = отклонённая заявка =
  MARGIN_CRASH процесса = конец ячейки. На фолдах раунда 4 ни одна из 12 ячеек J/S
  не набрала 30 наблюдаемых сделок, потому что классы не доживают до журнала.
- **D показал свой хвост:** 5/6 фолдов — LIQUIDATED/MARGIN_CRASH; обе ETH-лесенки

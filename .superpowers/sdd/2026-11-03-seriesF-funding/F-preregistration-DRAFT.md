## 1. Механизм (гипотеза)

Хвостовой фандинг = перегретая толпа: z ≥ +θ ⇒ шорт перпа (получаем carry + fade
разворота), z ≤ −θ ⇒ лонг. Источник профита заявлен как ДВА потока: (а) carry-касса
за холд (C2) и (б) возврат перекоса цены (directional). Зонд обязан разложить net на
price и carry — если прибыль вся price, а carry-ноль, это ставка на знак фандинга,
как в D-0 §3; решение о freeze принимается по разложению, не по totals.

Отличие от убитых классов (почему это НЕ resurrection):
- против B (θ-порог raw-rate, 5.3 такта/круг): здесь событие = статистический хвост
  z, частота в разы ниже, холд 24–96ч фиксирован (не флипы знака каждый такт);
- против D-V1 (решение по знаку каждой расчётки, 83 круга/эпоха): вход только в хвосте,
  position-based неперекрывающиеся сделки r3;
- против r3 (dead): r3 мерла n=19<30 при окне 333д на ОДНОМ наборе фолдов — F несёт
  НОВУЮ нетронутую эпоху BTC-2024 (11 мес, никогда не симулировалась) как первичное
  OOS-доказательство (C3), а не «ещё одно окно для той же смерти»: правила/оси
  замораживаются ЗДЕСЬ, до любых чисел BTC-2024;
- E-7 урок вшит: клетка, живущая только на ETH, НЕ является основанием (см. no-go).

## 2. Замороженные константы правила (до чисел)

- Сигнал: z_j = (r_j − μ / σ) по последним расчёткам rate в окне (ts_j − 90d, ts_j)
  (trailing 90d, ровно r3; μ/σ по всем расчёткам строго раньше ts_j; нужно ≥20 историч.
  расчёток, иначе сигнала нет).
- Пороги θ ∈ {1.5, 2.0, 2.5} (три уровня хвоста; 2.0 = прецедент r3, 1.5/2.5 = его
  окрестности, заранее, не по результатам).
- Направление: z ≥ +θ → SHORT N0; z ≤ −θ → LONG N0 (контр-толпа, обе стороны).
- Вход: close первого 1m-бара с ts ≥ ts_j + 3600 (close_{T+1h}, конвенция r3),
  adverse slip: long-entry ×(1+SLIP), short-entry ×(1−SLIP).
- Холд: H ∈ {24, 48, 96} ч ровно; выход = close последнего бара с ts ≤ entry_ts + H;
  принудительный выход последним доступным close < end эпохи.
- Неперекрываемость: одна позиция одновременно; сигнал во время холда ПРОПУСКАЕТСЯ
  (не флип) — r3 position-based.
- Carry: interior-расчётки холда (entry_fill_ts < ts_j < exit_fill_ts), как D-0:
  short при r>0 получает +r·N0, long — платит. Расчётка, породившая вход, не начисляется.
- Экономия: CAPITAL $10,000; lev=1 ⇒ N0=$10,000; FEE=0.0006·N0 на ногу; SLIP=0.0005;
  round-trip трение 0.22%·N0 = $22. Тейкер-экономика (maker-ось — отдельный enabler,
  здесь запрещена).
- Точность: float64 QA-уровень (он выбирает оси; боевой sim после freeze — Decimal).
  Базы mode=ro.

## 4. Pre-code NO-GO (зафиксирован до запуска, в этом коммите)

Зонд печатает для каждой клетки (sym × θ × H) по каждой эпохе: fee-net $ по thirds,
pooled $, %/год, кругов (RT), price/carry расложение, средний MAE%.

**Серия F НЕ пишется, если НЕ существует ни одной клетки-выжившей. Выжившая клетка =
эпоха, где одновременно:
 (F-a) fee-net ≥ 0 в КАЖДОМ thirds этой эпохи;
 (F-b) pooled ≥ +3.0%/год на $10k (планка §8, не ослабляется);
 (F-c) кругов (round-trips) ≥ 15 за эпоху (размерный пол probe-стадии; n≥30
  останется жёстким гейтом sim-стадии);
 (F-d) максимум MAE ≤ 50% N0 (lev1-стресс: 24–96ч холд не должен касаться зоны
  ликвидационной дистанции).
ДОПОЛНИТЕЛЬНО (анти-E-7): если выжившие клетки есть ТОЛЬКО на ETH (ни одной BTC-клетки
ни в B1, ни в B2) — вердикт «NO-GO: ETH-привязка», пересмотр только через отдельный
DRAFT на форвардных данных. BTC B1 (нетронутая 2024) — приоритетное доказательство:
выживание только в B2 без B1 помечается «режим известной эпохи» и ведёт к докладу
владельцу, а не к автомату freeze.**

Ничего из §4 не смягчается post-hoc. Если зонд пограничен (одна клетка ровно на границе
гейта) — это тоже результат зонда, докладывается как есть; «ещё один порог» = threshold
shopping, запрещено.

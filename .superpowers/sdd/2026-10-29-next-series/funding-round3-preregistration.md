Гейт отправки: ревью братом `feat/funding-data` → merge в calibration-suite → живая

## 1. Класс и экономический приор

Класс: **контратarian на экстремумах funding-ставки (crowding/unwind) + carry-аккрюэл**.
Механизм: экстремальная положительная ставка = переполненная лонг-позиция → риск
разворота/выбивания → шорт после settle; экстремальная отрицательная = переполненный
шорт-толпа → топливо для squeeze → лонг. Побочный объект: сам аккрюэл funding на
удерживаемой позиции (лонг платит при rate>0, получает при rate<0).

Типичные ставки из живого dry-run: 0.005–0.008%/8h (BTC). Carry-капля за холд 24ч
≈ 3×|rate| — сама по себе не покрывает round-trip 0.22%; торговый объект — только
хвосты. Именно поэтому выживание требует ценовой составляющей (правило 5).

Урок rounds 1–2 (обязателен здесь): вход только честный `close_{T+1h}`, никаких
«сигнал в bаре, вход тем же close». Никакого мульти-символьного lead-lag — там эффект
оказался внутрибарной синхронностью.

## 3. Сигнал

Для каждого settle-момента T (ts из таблицы, ставка r_T известна в T):
- z_T = (r_T − mean_90d) / std_90d, окно = 270 предшествующих settle строго до T
  (r_T в окно НЕ входит; no-lookahead).
- Сигнал LONG, если z_T ≤ −θ; сигнал SHORT, если z_T ≥ +θ; **θ = 2.0 (зафиксирован)**.
- std_90d = 0 или окно неполное → сигнала нет.

## 4. Исполняемый объект (первичный)

Первичный объект — **неперекрывающиеся position-based сделки** (не per-event: при
сетке 8h и холде 24h событийный ряд накладывался бы втрое и раздувал n):
1. Рассматриваются только settle-моменты, когда позиция флоская.
2. Сигнал в T → вход по **первому доступному часовому close строго после T**
   (= close_{T+1h}, если бар на месте). Если ближайший доступный close позже T+3h —
   сделка помечается degraded и исключается из первичных средних (учитывается в
   диагностике).
3. Холд **24 часа**: выход по close_{T+25h} (первый доступный close ≥ T+24h+1h...
   конкретика: точка выхода = первый часововой close строго позже entry_время+24h;
   фиксируется в методологии брата до чисел).
4. Сигналы во время удержания игнорируются; после выхода следующий settle с сигналом
   открывает новую сделку.
5. Направление — только spot-прокси (long/short через знак позиции в расчёте), как в
   round 2; engine здесь не используется.

Колонки на сделку (все в % от нотинала):
- `price_only` — gross без комиссий: (exit−entry)/entry × sign.
- `accrual` — funding, капнувший на позицию: суммируем по каждому settle-моменту τ,
  для которого entry_время < τ ≤ exit_время: для LONG accrual = −Σ r_τ; для SHORT
  accrual = +Σ r_τ (положительная ставка платится лонгами). Ставки τ вне холда не
  считаются; τ = момент входа (ровно entry_время) не считается — позиция открыта ПОСЛЕ
  этого settle.
- `combined` = price_only + accrual.
- `net` = combined − 0.22% (round-trip taker; slippage 0 в этом раунде — фиксируем
  одинаково для всех ячеек).

## 5. Первичные ячейки (их ровно 4)

| Ячейка | Актив | Сигнал | Направление | Окно измерения |
|---|---|---|---|---|
| F1 | BTC | z ≤ −2 | LONG | f0+f1+f2+f3 |
| F2 | BTC | z ≥ +2 | SHORT | f0+f1+f2+f3 |
| F3 | ETH | z ≤ −2 | LONG | f1+f2+f3 |
| F4 | ETH | z ≥ +2 | SHORT | f1+f2+f3 |

Ожидаемый n (априори, до чисел): BTC ~2900 settle в окне, хвосты ±2 ≈ 2–5% → 60–150
событий на хвост, после схлопывания в неперекрывающиеся — порядка десятков–сотни;
ETH — 20–50 событий на хвост. Это не обещание, а калибровка честности: если n < 30,
ячейка умирает по правилу 1 и так и публикуется.

## 6. Правила выживания (все 5 условий; любое нарушение = кандидат мёртв)

По combined-колонке ячейки:
1. **n ≥ 30** неперекрывающихся сделок в окне измерения;
2. **gross-средняя combined ≥ +0.30%** (тот же порог, что rounds 1–2);
3. **средняя combined > 0 во всех фолдах** окна (BTC: f0,f1,f2,f3; ETH: f1,f2,f3);
4. **bootstrap 95% ДИ нижней границы средней combined > 0** (1000 ресемплов, iid по
   сделкам; перекрывание уже снято position-based объектом);
5. **структурный страж: средняя price_only > 0** — стратегия не должна жить только
   на carry-капле; ценовая составляющая обязана быть направленной.

Вердикт раунда: ≥1 выжившая ячейка → ведущий готовит дизайн-черновик кандидата под
owner-гейт (R-next-4). Ноль выживших → раунд 3 закрывается, класс funding/carry
заносится в реестр убитых с красными таблицами.

## 8. Диагностика (не является материалом для спецификаций)

Всё остальное публикуется как диагностика, с явной пометкой «не для спецификации»:
- лестница холдов k ∈ {8, 16, 32, 48}h при θ=2;
- лестница θ ∈ {1.5, 2.5, 3.0} при k=24h;
- лестница trailing-окна {30, 60, 180}d при θ=2, k=24h;
- percentile-версия хвоста (5/95 перцентиль trailing 90d) — альтернатива z-оценке;
- momentum-вариант: Δz > 0 при уже |z|≥θ (экстремальность нарастает — continuation?);
- net-колонка после 0.22% (для контекста стоимости);
- вклад top-3 сделок в среднюю ячейки (устойчивость к одному эпизоду);
- средняя длина эпизода |z|≥2 (в settle);
- разбивка по режимам волатильности (trailing 30d std доходности, медианная отсечка).

Бюджет ячеек раунда: 4 первичные + ≤36 диагностических = ≤40. Брат по завершении
указывает фактический итог бюджета в шапке файла ответа.

## 10. Что произойдёт после вердикта

  остаются в ядре как починенный фундамент; следующий раунд выбирается заново через
  council-черновик и owner-гейт.

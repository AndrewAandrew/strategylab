# Series V — FREEZE DRAFT (решётка sim ≤18) — ПРОЕКТ лида, ОЖИДАЕТ «ок» владельца

Статус: предлог заморозки sim-решётки Series V по результату V-0 зонда (GO AT PROBE,
коммит `5bbc203`). Оси замораживаются **правилом по честным live-клеткам зонда**, НЕ
рангом/выбором победителя. Это НЕ сим-код и НЕ прогон решётки — sim-код и grid-раннер
пишутся только после отдельного «ок» владельца (прецедент E-2-F). Все числа ниже — из
`V0-zone-deviation-probe-raw.txt` (sha256 `987c77a2…d048`), уже замороженного артефакта.

## 3. Live-гейт для sim-стадии (ужесточение ДО решётки, не постфактум)

Из диагноза V-0 (§2 вердикта): конвенция E-0 «пустая треть = net 0 = V-a пройдена»
награждает поздний листинг (SOXL: 779 live, 0 с 3/3 непустыми). Предлагаемое правило
заморозки (заявляется сейчас, до сим-чисел, применяется ко ВСЕМ рынкам одинаково):

  **треть засчитывается в V-a только если nq(треть) ≥ 3 круга.** Клетка жива, если
  все ТРИ трети имеют nq≥3 **И** net≥0 в каждой **И** pooled ann≥+3.0%/год **И** n≤75.

Это УЖЕСТОЧЕНИЕ (убирает false-positive вакуума), а не смягчение. Оно НЕ меняет вердикт
V-0 (тот = GO по замороженному pre-code правилу §5 DRAFT, где вакуум-треть явно
разрешён как «q=(0/0/0)»). Применяется только к будущей sim-решётке. Под это правило
честно выживают (из V-0 числа, как пред-проверка): ZEC V2_R1 (nq=1/7/3 — 1-я треть nq=1<3
⇒ по новому правилу СОХРАНЯЕТ только если сим-данные плотнее зонда) и SOL V1_48
(nq=14/2/9 — 2-я треть nq=2<3 ⇒ погранична). Это честно: на РЕАЛЬНОЙ решётке по
плотным рынкам (SOL — полный span) третьи должны наполниться; на SOXL ранняя треть так и
останется структурно пустой → SOXL по новому правилу, вероятно, отсеется сам собой.

## 4. Три решения, нужны от владельца («ок»)

1. **Написать sim-код** (Decimal, боевой, прецедент C-0/D-0) и гонять решётку §2 — сейчас
   НЕ пишу без «ок» (E-2-F).
2. **Принять live-гейт nq≥3/треть** (§3) как условие заморозки — чтобы не награждать вакуум.
3. **Выбрать приоритетный рынок для one-shot холдаута** (аудит §2/C3, E-7: ровно ОДИН
   холдаут-флаг на серию, потом нельзя «ещё одно окно»):
   - **ZECUSDT** — ann +33.7…+36.2%/год, оборот ниже (n=11…23), толстая вторая треть;
   - **SOLUSDT** — ann +12.6%/год но n=25, статистически самый мощный, полный span 180д;
   - SOXLUSDT — лид НЕ рекомендует (структурно неполный fit-history + 3x-ETF продукт).
   Лид рекомендует **SOLUSDT** как холдаут (стат. мощность > амплитуда; ann ZEC может быть
   режим-выборкой из одной плотной трети), но решение за владельцем.

## 5. Порядок, если владелец даст «ок»

ветка + TDD (unit: зоны/события/rounds/gates; fresh-eyes review) → gates (pytest зелёный)
→ grid-раннер (заморозка osей §2, live-гейт §3) → сим-числа публикует **брат-mimo**
(R-next-1: sim/holdout grid + первая публикация grid-чисел) → один one-shot холдаут на
чистом окне выбранного рынка [1790294400,1791849600) → вердикт. Никакого докручивания
осей после холдаута. Холдаут сегодня не тронут (HOLDOUT-GUARD V-0 = 0 чтений).

## 6. Чего этот DRAFT НЕ делает

- Не объявляет серию «рабочей» — только что она пережила зонд; wall-тест = холдаут.
- Не меняет вердикт V-0 (GO по pre-code правилу).
- Не пишет sim-кода и не гоняет решётку (требует «ок» владельца).
- Не резервирует холдаут-окна всех трёх рынков (зарезервируется ровно одно, выбранное).

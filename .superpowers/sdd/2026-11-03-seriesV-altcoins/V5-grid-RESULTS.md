## Метод пересчёта (рука замерщика, Decimal)

- Круг = пара entry→exit подряд из `*_journal_p.csv`; net круга = `cash_delta(entry) + cash_delta(exit)` (Decimal, полная точность строки журнала); ts круга = ts события = `entry_ts` (§4 amendment).
- Трети: `t = (entry_ts − 1774742400) // 5184000` (60d = 5184000 с; окно ровно 180d = 3 трети):
  t0 [1774742400, 1779926400) = 2026-03-29..2026-05-27 (граница 05-28 00:00 UTC),
  t1 [1779926400, 1785110400) = 2026-05-28..2026-07-26,
  t2 [1785110400, 1790294400) = 2026-07-27..2026-09-24.
- `nq` = число кругов в трети, `q$` = сумма net по трети; `n` = всего кругов; `net$` = сумма всех кругов; `ann% = net/10000 × 365/180 × 100` (pooled, 180d).
- Гейты §4 (frozen, дословно): **V-a'** — во всех трёх третях `nq ≥ 3` И `net ≥ 0`; **V-b'** — pooled `ann ≥ +3.0 %/год`; **V-c'** — `n ≤ 75`. Клетка LIVE ⟺ V-a' ∧ V-b' ∧ V-c'; иначе dead. Никаких иных критериев при выставлении LIVE/dead не применялось.

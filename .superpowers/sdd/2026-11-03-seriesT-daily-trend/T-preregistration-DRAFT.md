# Series T — Daily trend (Donchian×ATR-stop) — ПРИРЕГИСТРАЦИОННЫЙ DRAFT (2026-11-03)

Статус: DRAFT лида, ТОП-5 позиция №4 глобального аудита (коммит 7ad653e, критерии
C1–C5 заморожены до чисел). Зонд T-0 read-only разрешён standing-приказом владельца.
Freeze sim-решётки — отдельное «ок» после вердикта (как E-2-F).

## 1. Гипотеза и происхождение

Незакрытая ветка реестра R3-B: «дневной тренд никогда не симулировался, cost-ratio к
трению на 1d в ~10× лучше». spec_01 умер как 15m-класс (PF 0.40/0.45, мёртв даже при
нулевой комиссии — do-not-resurrect на 15m Donchian). 1d — ДРУГОЙ класс: оборот
единицы кругов в год, gross-хвост трендового года переносит 0.22%/круг легко (C1✔✔✔).
Живое внешнее знание: тренд-фолюинг на дневках — самый воспроизводимый академически
крипто-сигнал. Лаборатория его НИ РАЗУ не меряла.

## 2. Замороженное правило зонда (оси = будущая решётка, новых не появится)

- Данные: 1d OHLC из bars_1m (UTC-сутки; первый open/макс high/мин low/последний close),
  сегменты непрерывности: A = BTC [2024-01-01, 2025-01-01), B = BTC/ETH
  [2025-10-27, 1790294400). HARD-GUARD: чтения ts ≥ 1790294400 нет (как в F-0).
- Сигнал по закрытию дня t: DONCHIAN-N long-breakout, c_t > max(c_{t−N..t−1}) → want +1;
  c_t < min(c_{t−N..t−1}) → want −1; между — want = текущая позиция (hold тренда).
  N ∈ {20, 55, 100} дней. Warmup: нужен N полных дней истории ВНУТРИ сегмента, первые
  сигналы с A_start+N / B_start+N; пустые начала отпечатаны явно.
- Исполнение: решение по close_t → вход/выход/реверс по OPEN дня t+1, adverse slip
  (long-entry ×(1+SLIP), exit ×(1−SLIP)); реверс = exit по open + entry по тому же open
  (2 ноги, 1 сделка считается закрытой, новая открыта).
- Стоп: ATR14 = среднее TR за 14 завершённых дней до дня входа; стоп-уровень в момент
  входа: long entry_fill − k·ATR (short симметрично), k ∈ {1, 2, 3}. Проверка стопа по
 _intrabar_ каждого дня держания, начиная со дня входа: если open ≤ stop ⇒ выход по
  open (гэп, честная цена), иначе если low ≤ stop ⇒ выход по stop. Выход стопа — в
  флэт; вход обратно только по новому breakout.
- Funding-нога (перп, не спот): interior-расчётки холда начисляются по конвенции D-0
  (long платит при r>0) — дневной холд по 20–100 дней обязан нести эту кассу,
  иначе метрика врёт (Правило 6-мышление).
- Экономика: CAPITAL $10,000 = N0 (lev=1); FEE 0.0006·N0 на ногу; SLIP 0.0005;
  круг = 2 ноги = $22. float64 QA, режимы БД mode=ro, двойной байт-identical прогон.

## 3. Метрики

Для каждой клетки (sym × N × k) по эпохам A(BTC-2024), B-BTC, B-ETH:
net $ по каждой из 3 четвертей эпохи (сделка целиком в трети дня выхода; пустая треть
печатается n=0 и считается выполненной вакуумно — как F-0), pooled $, %/год =
pooled/10k/(календ.дней эпохи/365), RT (число входов), price$ / carry$ расложение,
max MAE % от N0.

## 4. Pre-code NO-GO (замораживается ЭТИМ коммитом, до любых чисел; строже аудита)

Клетка-выжившая в эпохе A (BTC-2024 — ПЕРВИЧНОЕ нетронутое доказательство):
 (T-a) fee-net ≥ 0 в каждой НЕПУСТОЙ четверти эпохи A;
 (T-b) pooled ≥ +3.0%/год (планка §8 не ослабляется);
 (T-c) RT ≥ 3 в эпохе A (меньше — единица удачи; sim-стадия потом потребует свой n-пол);
 (T-d) max MAE ≤ 50% N0.
**Серия T не пишется, если нет ни одной выжившей клетки в эпохе A.** Эпохи B —
корроборация, НЕ основание: выживание только в B ⇒ «NO-GO: нет подтверждения на
нетронутом 2024» (C3-дух аудита; E-7/F-lesson). Выживание в A, но с cells-B сильно
отрицательные — докладывается как есть, owner решает по freeze. Пограничное =
результат как есть; спуск N/k/RT-пола post-hoc = threshold shopping, запрещено.
Бонус-строгость против F: там было «любая эпоха», здесь — именно нетронутая A
(аудит для T так и писал: «fee-net pooled < +3%/год на нетронутом BTC-2024 ⇒ не писать»).

## 5. Порядок

T-0 зонд → вердикт → если выжившая: доклад владельцу → «ок» → freeze решётки ≤9
(3N×3k, первичный символ BTC; ETH = вторичный) → sim-ветка TDD → замерщик R-next-1 →
гейты 1–6+bootstrap → one-shot холдаут. Холдаут T: BTC [1790294400, 1793577600) —
НО он уже зарезервирован аудитами? Нет: one-shot холдаут каждой серии берётся из ЧИСТОГО
окна; BTC-окно пока никто не трогал (F умерло до него). Если T доживёт до F-7-аналога,
холдаут = BTC-окно [1790294400,1793577600); вторая серия на том же окне НЕ допускается —
кто дожил тот и занимает (фиксация приоритета: порядок выживания P2-зондов). Если к тому
моменту ETH-форвард [1793577600,+∞) достаточно дорастёт — предпочесть ЕГО и сохранить
BTC-окно для следующего выжившего. Решение — в freeze-DRAFT, не здесь.
Если нет — PRE-CODE NO-GO, дальше K-0 (carry контракт-холд, funding-BTC-2024 уже
«известна» после F-0 ⇒ primary окно K = эпоха B + форвард, честно объявить в K-DRAFT).
